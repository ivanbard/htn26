## Core Gameplay Loop

### 1. Order Appears

The central game displays an order:

**Example:** 🍔 Burger

- Bread
- Cooked meat
- Lettuce
- Cheese, if required

A timer starts for that order.

### 2. Grab an Ingredient

Players collect ingredients from one of two pantry areas:

- **Pantry NFC tag:** Bread or lettuce
- **Fridge NFC tag:** Cheese or meat

The player taps their ESP32 badge on the appropriate NFC tag.

Example:

`Player 1 → Fridge`

The player then selects or receives an available ingredient from that location.

The badge sends:

`PLAYER_1 picked up RAW_MEAT`

or:

`PLAYER_1 picked up CHEESE`

Players can carry one item at a time initially.

The server tracks which ingredients are available at each location and removes the selected ingredient from the player's inventory.

### 3. Process an Ingredient

Players physically move to the required processing area and tap their badge on the corresponding NFC tag.

#### Cutting Board Area

The cutting board is used for ingredients that need to be chopped or prepared.

Examples:

`RAW_MEAT → Cutting Board → CHOPPED_MEAT`

`LETTUCE → Cutting Board → CHOPPED_LETTUCE`

The player taps the cutting board area while carrying the ingredient. Processing takes a few seconds.

#### Stove Area

The stove is used to cook ingredients that require heat.

Example:

`CHOPPED_MEAT → Stove → COOKED_MEAT`

Processing can take a few seconds. If the player leaves the ingredient on the stove for too long, it may become burnt.

For the first version, use a simple interaction:

`Tap station → wait 3–5 seconds → ingredient processed`

The player may need to:

- wait
- press a button repeatedly
- shake or move the ESP32
- hold a button

These additional interactions can be added later if time allows.

### 4. Dispose of an Item

If a player wants to throw away the item they are carrying, they press the **B button** on their badge.

Pressing B begins the disposal action, but the item is not discarded immediately. To confirm that they want to throw it away, the player must:

1. Press and hold the **B button**.
2. Shake the badge aggressively while continuing to hold B.

Once the badge detects the required shake motion, the item vanishes from the player's inventory.

Example:

`Player 1 holding BURNT_MEAT → Hold B + shake badge → Item discarded`

This confirmation prevents players from accidentally throwing away ingredients.

### 5. Put Ingredients on a Plate

Once an ingredient is ready, the player places it on a plate.

The player taps a **plate NFC tag** while holding an ingredient.

Example:

`Plate 1`

- Bread
- Cooked meat
- Lettuce
- Cheese

The server stores the plate contents.

The physical plate itself does not need electronics beyond an NFC tag.

Players can add ingredients to the plate in any order, as long as the final contents match the active order.

### 6. Serve the Plate

The player brings the completed plate to the **Serving Station**.

They tap:

`Plate → Serving Station`

The server checks the plate against an active order.

If the ingredients and preparation states are correct, the order is completed. If the plate is missing ingredients or contains incorrect ingredients, the server rejects it or applies a penalty.

### 7. Score

If the order is correct:

`ORDER COMPLETE +100`

Bonus points can be awarded for:

- Fast completion
- Correct ingredients
- Order streaks
- Serving multiple orders efficiently

Penalties can be applied for:

- Wrong ingredients
- Burnt food
- Missed orders
- Discarding useful ingredients
- Serving an incomplete plate

### 8. Repeat

New orders continuously appear.

As more orders pile up, players need to divide responsibilities:

`Player 1 → pantry and fridge`

`Player 2 → cutting board and stove`

`Player 3 → plating and serving`

Players may also switch roles depending on which ingredients and stations are currently needed.

This creates the cooperative chaos of Overcooked while requiring players to physically move between the pantry, fridge, cutting board, stove, plates, and serving station.

## ESP32 Responsibilities

Keep the badges intentionally lightweight.

**ESP32 handles:**

- Player ID
- NFC scans
- Button and IMU input
- Detecting the hold-and-shake disposal confirmation
- Small display and LEDs
- Sending actions over Wi-Fi

**Raspberry Pi or laptop handles:**

- Orders
- Available ingredients in the pantry and fridge
- Player inventory
- Ingredient states
- Cutting board processing
- Stove cooking timers
- Burnt food states
- Plate contents
- Disposal validation
- Score
- Game timer
- Order validation

Example station message:

`{ player: 2, station: "fridge" }`

Example ingredient pickup message:

`{ player: 2, action: "pickup", location: "fridge", item: "RAW_MEAT" }`

Example processing message:

`{ player: 2, station: "cutting_board", item: "LETTUCE" }`

Example disposal message:

`{ player: 1, action: "discard", item: "BURNT_MEAT" }`

The server decides whether the action is valid and updates the game state.

## Physical Stations

For the MVP, use four main NFC tags:

### Pantry NFC Tag

Contains:

- Bread
- Lettuce

Players tap the pantry tag and select or receive one of the available ingredients.

### Fridge NFC Tag

Contains:

- Cheese
- Meat

Players tap the fridge tag and select or receive one of the available ingredients.

### Cutting Board NFC Tag

Used to process ingredients that need to be chopped or prepared.

Examples:

- Meat
- Lettuce

### Stove NFC Tag

Used to cook ingredients that require heat.

Example:

- Chopped meat

### Other Game Objects

The game can also include:

- Plate NFC tags
- Serving Station NFC tag
- Optional disposal area

The disposal action does not require a physical trash station because it is confirmed directly through the player's badge.

Each station or object can simply use an NFC tag, while the Raspberry Pi or laptop manages the game logic.
